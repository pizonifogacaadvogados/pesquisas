## Síntese

**Música e SFX (licença).** Nenhuma biblioteca gratuita dá cobertura explícita a **campanha política**, e a Pixabay a **proíbe expressamente**. Ordem recomendada:
1. **Política/campanha:** só **Freesound CC0** (efeitos) e faixas **CC0/domínio público** (FMA ou YouTube Audio Library com licença CC0/sem atribuição, verificando faixa a faixa), ou trilha própria/contratada com cláusula de uso eleitoral. **Nunca Pixabay** (R19.04). Uppbeat e Mixkit não falam em uso político (R19.08), então só com confirmação por escrito. Guardar o print da licença de cada faixa no pacote do vídeo.
2. **Escritório (comercial):** YouTube Audio Library na "licença padrão" (sem crédito) é segura **no YouTube**. Para Reels/TikTok/LinkedIn, preferir faixas CC BY (crédito na legenda) ou CC0. A Mixkit Free License serve em redes e anúncios online, sem crédito. Pixabay serve (sem crédito), mas com risco de Content ID. Uppbeat grátis **não** serve (exige Business para empresa ou anúncio).
3. **Evitar sempre:** NC (BY-NC, BY-NC-SA: o FMA veda inclusive arrecadação e promoção) e ND (impede sincronizar com vídeo).
4. Sugestão de regra para `conformidade.py`: campo `licenca_trilha` ∈ {cc0, cc-by, yt-padrao, mixkit-free, pixabay, proprio}; bloquear `pixabay` e `nc/nd` em perfil político, e exigir crédito se `cc-by`.

**Imagem (ffmpeg, CPU).** O material do sistema é renderizado e limpo, então denoise quase não faz diferença. Para **nitidez de legenda/texto**, usar `unsharp` leve, que custa só cerca de +1 s em 41 s. **Não usar `nlmeans` no padrão** (568 s para 41 s). Reservar o `nlmeans` rápido só para footage de celular com ruído visível, e em lote.
```bash
# padrão (vídeo do sistema / celular bom): nitidez leve, ~+20% de tempo
ffmpeg -i in.mp4 -vf "unsharp=5:5:0.6:3:3:0" -c:v libx264 -preset veryfast -crf 18 -c:a copy out.mp4
# celular com ruído leve (pouca luz): denoise temporal barato + nitidez adaptativa (~2x a base)
ffmpeg -i in.mp4 -vf "hqdn3d=1.5:1.5:6:6,cas=strength=0.5" -c:v libx264 -preset veryfast -crf 18 -c:a copy out.mp4
# ruído forte, só se der tempo (~3x o tempo real em 540x960; 1080p deve ser ~4x mais lento)
ffmpeg -i in.mp4 -vf "nlmeans=s=2:p=3:r=7,unsharp=5:5:0.5:3:3:0" -c:v libx264 -preset veryfast -crf 18 -c:a copy out.mp4
```

**Batida.** **aubio** é o mais leve e o mais preciso no teste (F 0,91, 0,13 s, cerca de 1 MB), mas **não tem wheel** para Python 3.13 (compila C, e o build é frágil desde o 3.12). **librosa** instala fácil (wheel puro), mas puxa cerca de 410 MB (numba/llvmlite/scipy/sklearn), tem 11 s de aquecimento numba e o `beat_track` errou a fase no teste. Recomendação: **manter o `audio.batidas()` em numpy** (zero dependência) e melhorá-lo com a ideia do aubio, isto é, estimar o período por autocorrelação do fluxo espectral e escolher a fase que maximiza o fluxo no grid. Isso eliminaria os falsos positivos do contratempo (P 0,50 → próximo de 0,9). Se for adotar biblioteca, use aubio num venv opcional:
```bash
python3 -m venv .venv-audio && .venv-audio/bin/pip install numpy setuptools && .venv-audio/bin/pip install aubio==0.4.9   # compila; pode falhar no 3.13
.venv-audio/bin/python -c "import aubio;s=aubio.source('m.wav',44100,512);t=aubio.tempo('default',1024,512,44100);b=[]
while True:
  x,r=s();  b+= [t.get_last_s()] if t(x) else []
  if r<512: break
print(t.get_bpm(), b)"
```
